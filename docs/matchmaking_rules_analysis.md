# 小队匹配规则梳理与竞品对标分析

> **信息源说明**：本文档基于 2024-2025 年间各游戏最新版本（测试服/正式服）的公开机制整理。
> **核心参考**：仗剑传说 (ZhangJian ChuanShuo / 雷霆竖屏放置)、魔兽世界 (WoW)、燕云十六声 (Where Winds Meet)、阿尔比恩 (Albion Online)。

## 1. 核心竞品机制总览

### 1.1 仗剑传说 (ZhangJian ChuanShuo)
*   **定位**：竖屏放置/卡牌RPG，强调轻量化社交与数值验证。
*   **匹配核心**：**“助战”与“职业互补”**。作为放置类游戏，其匹配机制虽然弱化操作，但强调职业搭配（贤者/骑士优先），并引入AI助战解决等待问题。
*   **信息源**：2025年公测版本及社区反馈（雷霆代理）。

### 1.2 魔兽世界 (WoW)
*   **定位**：传统战法牧MMORPG。
*   **匹配核心**：**“职能匹配”与“动态等级”**。通过地下城查找器 (LFG) 实现跨服、跨阵营匹配，严格遵循坦克/治疗/输出的铁三角架构。
*   **信息源**：11.0 地心之战 (The War Within) 版本机制。

### 1.3 燕云十六声 (Where Winds Meet)
*   **定位**：开放世界武侠，单人/多人模式并存。
*   **匹配核心**：**“主客机机制”与“无缝社交”**。多人模式基于房主世界，强调小范围（2-5人）的沉浸式探索与话本攻坚，支持AI队友。
*   **信息源**：2024年“仲吕测试”及后续测试版本。

### 1.4 阿尔比恩 (Albion Online)
*   **定位**：沙盒MMORPG，装备驱动。
*   **匹配核心**：**“软性战力限制”与“低门槛竞技”**。竞技场 (Arena) 和远征 (Expedition) 采用IP (Item Power) 软上限机制，拉平数值差距以保证体验。
*   **信息源**：2024-2025年 Crystal Arena 赛季规则。

## 2. 匹配规则详细梳理

### 2.1 匹配池 (Matchmaking Pool)

| **匹配范围** | **全服/跨服**<br>基于房间列表或自动匹配，池子较宽。 | **跨服 (Cross-Realm)**<br>覆盖整个大区，近期打通了跨阵营组队。 | **跨服/跨节点**<br>基于大世界位面，可跨服邀请，但匹配主要基于当前时段活跃池。 | **全服 (Single Server)**<br>全球同服（或分亚/美/欧服），匹配池极大。 |

### 2.6 匹配优先级 (Priority)

1.  **魔兽世界 (WoW)**:
    *   **第一优先级**：**职责平衡** (Tank > Healer > DPS)。
    *   **第二优先级**：**等待时间** (Time in Queue)。
2.  **仗剑传说 (ZhangJian ChuanShuo)**:
    *   **第一优先级**：**职业互补** (Class Synergy)。系统倾向于优先匹配**贤者(辅助/奶)**进组，以提高队伍生存率。
    *   **第二优先级**：**战力区间** (CP Range)。匹配战力达标的玩家。
    *   **第三优先级**：**社交关系** (Social)。好友或公会成员优先。
3.  **阿尔比恩 (Albion)**:
    *   **第一优先级**：**MMR/段位** (Skill Rating)。
    *   **第二优先级**：**预组队匹配预组队** (Premade vs Premade)。
4.  **燕云十六声**:
    *   **第一优先级**：**房主网络/地理位置** (Connection)。
    *   **第二优先级**：**世界等级相近** (World Level)。

## 3. 核心竞品场景化匹配逻辑深度剖析

本节采用“核心机制 - 玩法模式 - 实际体验”的三层结构，对竞品进行深度拆解。

### 3.1 阿尔比恩 (Albion Online) —— 装备驱动的硬核分层

#### 一、 核心机制：没有“人物等级”，只有“装备强度” (IP)
首先要纠正一个概念： **Albion 没有人物等级（Level 1-100）** 。
取而代之的是 **Item Power (IP，物品强度)** 。你的强度完全取决于你穿了什么装备（Tier 4 到 Tier 8）以及你的技能专精（Spec）。
因此，匹配系统看的是你的 **IP** 和 **角色定位（Tank/Healer/DPS）** 。

#### 二、 两种截然不同的“副本”模式
Albion 的 PVE 内容分为两类，匹配逻辑完全不同：

**1. 远征（Expeditions）—— 类似于 WoW 的随机本**
这是 Albion 中唯一有 **自动匹配系统** 的玩法，通常位于主城（Royal Cities）的蓝色传送门处。
*   **匹配规则**：
    *   **硬性 IP 门槛**：比如 T6 远征（Hardcore Expedition, HCE 的前置），系统要求你至少有 1000 IP 才能点击匹配按钮。
    *   **软性 IP 软顶（Soft Cap）**：为了防止高装等玩家碾压低级远征，系统设有 **IP 软上限** 。比如在 T4 远征中，超过 1000 IP 的部分会被削减 80%。这保证了 T8 大佬进来打 T4 远征也不会像 WoW 那样一刀秒怪，依然需要按流程打。
    *   **职能匹配**：严格遵循 **1坦克 + 1治疗 + 3输出** 。

**2. 随机地下城（Random Dungeons, RD）—— 真正的核心玩法**
这是 Albion 玩家 99% 的 PVE 时间所在，位于野外（蓝区/黄区/红区/黑区）。
*   **注意：这类副本没有任何自动匹配系统！**
*   **纯社交驱动（LFG）**：你想打 T8 蓝洞（Group Dungeon）？你必须在聊天频道（/lfg 频道）喊人：“T8 Map FF, LF Tank/Healer 1300+ IP”。或者你需要加入一个公会（Guild），在公会频道组队。
*   **没有系统帮你组队**，你必须自己组齐 5-7 个人，然后一起骑马跑到洞口进去。
*   **跨度与门槛**：
    *   **完全由玩家决定**：队长说“必须 1500 IP 才能进”，那你 1499 IP 都会被踢。队长说“带萌新，T4 平装随便来”，那你穿新手装也能进 T8 本。
    *   **风险机制（红/黑区）**：在高级区域打本，副本入口可能会被敌对阵营玩家入侵（Dive）。如果你们队伍里带了太多低 IP 萌新，会被敌对玩家杀人越货，装备全爆。

**3. 高级玩法：HCE（硬核远征）**
这是 Albion PVE 的终局玩法之一，位于主城，虽然有匹配入口，但 **实际上全是预组队** 。
*   **机制**：使用高级地图（Map）开启的高难度副本，怪物伤害极高。
*   **匹配现状**：理论上可以用系统匹配，但 **实际上没人用** 。因为 HCE 对装备和配合要求极高（通常要求 1600-1800+ IP，特定配装，特定跳怪路线）。如果你用随机匹配进去，大概率是因为队友乱引怪导致灭团修装备亏本。
*   **社区规则**：HCE 玩家通过私聊频道（HCE Discord）组建固定队，严格筛选队友。

#### 三、 体验总结：残酷的“不抱团就死”
*   **如果你是一个 T8（顶级） 玩家，想去打 T4（低级） 副本**：
    *   **普通远征（主城排队）**：可以排，秒进。
        *   *体验*：你的属性被大幅压缩，打得比萌新快一点，但没法秒天秒地。你会觉得非常无聊，而且收益连修装备都不够。
    *   **野外蓝洞（Group Dungeon）**：没法排，得自己跑过去。
        *   *体验*：你可以一个人单刷（Solo）T4 的 5 人本。这时候没有系统压缩你的属性，你真的是一刀一群怪，非常爽，刷钱效率很高（很多高 IP 玩家会去蓝区单刷蓝洞赚钱）。
*   **社交性**：Albion 强迫你社交。除了最低级的远征，所有高收益内容都需要你自己喊话组队、加公会、上 Discord 语音。它没有“点击就送”的匹配体验。

### 3.2 魔兽世界 (WoW) —— 工业化的双轨制社交

#### 一、 核心机制：装等 (Item Level) 与 职能 (Role)
WoW 的核心是 **“战法牧”铁三角** 和 **装等门槛**。所有匹配都基于这两个硬性指标。

#### 二、 两种截然不同的“组队”模式

**1. 地下城查找器 (Dungeon Finder / LFD) —— 自动化的快餐体验**
*   **适用场景**：升级路上的普通本、满级后的英雄本 (Heroic)、时空漫游。
*   **匹配规则**：
    *   **自动匹配**：你选择职责（T/N/D），系统自动把你塞进一个跨服队伍。
    *   **数值压缩**：低级玩家和满级玩家可以排同一个本，系统会将所有人的数值动态调整到副本等级。
    *   **社交体验**：**极度冷漠**。进本说句“hi”，打完说句“gg”，全程可能没有任何交流。如果有人掉线，系统会像换电池一样秒补一个新人进来。

**2. 预组队列表 (Premade Group Finder) —— 精英主义的简历模拟器**
*   **适用场景**：史诗钥石 (Mythic+)、团本 (Raid)、评级战场。
*   **匹配规则**：
    *   **手动申请**：队长挂出钥匙“10层 仙林 来熟练工”，你申请加入。
    *   **简历筛选 (Raider.IO)**：系统虽然只显示装等，但玩家社区会使用插件 (Raider.IO) 查看你的“大秘境评分”和“通关记录”。
    *   **残酷的门槛**：如果你是 610 装等但没有分，申请 100 个队伍可能被拒绝 99 次。
    *   **社交体验**：**高压且功利**。为了过本，大家会进行战术沟通，但一旦失误（黑钥匙），队伍可能瞬间解散并伴随争吵。

#### 三、 体验总结：效率至上的分裂社群
*   **新手/休闲玩家**：活在 LFD 系统里，虽然能一直有本打，但永远体验不到核心乐趣，也交不到朋友。
*   **核心玩家**：活在 Premade 系统里，每天像投简历一样申请进组，或者组建自己的“车队”（固定队）。
*   **Beagle 启示**：WoW 证明了 **自动匹配 (Auto-Match)** 极其高效但扼杀社交；**手动组队 (LFG)** 社交性强但门槛极高，容易劝退独狼。

### 3.3 仗剑传说 (ZhangJian ChuanShuo) —— 放置类的数值验证

#### 一、 核心机制：战力 (CP) 绝对主导，职业为辅
*   **战力门槛 (CP Threshold)**：作为数值游戏，一切以 **战力 (CP)** 为核心。副本通常设有推荐战力，匹配系统首先筛选 CP 达标的玩家。
*   **职业互补 (Class Synergy)**：虽然是放置，但高难本（如爬塔/传奇副本）存在 **“战法牧”硬需求**。
    *   **骑士 (Knight)**：必须要有，提供嘲讽与护盾，否则后排秒躺。
    *   **贤者 (Sage)**：必须要有，提供复活和续航。
    *   **术士/斗士 (DPS)**：提供输出。
    *   *深度细节*：纯 DPS 队伍在同战力下极易灭团，因此系统在匹配时会尝试（但不强制）凑齐铁三角。

#### 二、 副本匹配模式：零等待的“自动流”

**1. 自由匹配 (Free Match) —— 效率优先**
*   **机制**：点击“快速匹配”，系统在 **跨服战区 (Battle Zone)** 内寻找 CP 相近的玩家。
*   **AI 填充 (Bot Fill)**：**这是其最核心的体验保障**。
    *   **触发条件**：匹配时间超过 10-30秒 未组满。
    *   **AI 行为**：系统生成与副本难度匹配的“机器人队友”。这些 AI 会自动使用标准技能循环，且通常数值略高于及格线，保证能过本。
    *   **隐形规则**：玩家往往分不清队友是真人还是 AI（除非看名字/公会），这降低了“鬼服”带来的焦虑感。

**2. 队长带队 (Captain Mode) —— 针对性攻坚**
*   **机制**：队长建立房间，通过世界频道/公会频道喊话邀请。
*   **目的**：为了应对 AI 无法处理的复杂机制（如特定集火、躲避），或者为了“拖尸”（带低战力小号）。
*   **匹配逻辑**：**战力总分匹配**。系统会根据队伍的平均战力或总战力，匹配相应难度的动态敌人（或者进入固定难度的层级）。

#### 三、 体验总结：无压力的“陪伴感”
*   **零社交压力**：进本 -> 自动挂机 -> 领奖 -> 退出。全程无交流，甚至不知道队友是谁。
*   **AI 的双刃剑**：
    *   *好*：随时随地能打，不用求人。
    *   *坏*：极度削弱了人与人的链接。除了顶级高难本需要真人配合，90% 的时间玩家是在玩“单机”。
*   **Beagle 启示**：对于非硬核 MMO，**“能打”比“和谁打”更重要**。AI 填充解决了匹配的最痛点——**等待**。

## 4. Beagle 匹配算法规则详解 (基于体验分层)

基于用户体验的三个核心场景，结合《仗剑传说》的“战力区间匹配”逻辑，修正高战力玩家的跨服冲突问题，设计如下算法规则。

### 4.1 基础参数定义
*   **Player_CP (玩家战力)**：玩家当前的综合战斗力。
*   **Dungeon_Min_CP (准入战力)**：副本允许进入的最低战力。
*   **Dungeon_Cap_CP (碾压战力上限)**：系统判定的“正常开荒”战力上限（通常为推荐战力的 1.5倍 ~ 2倍）。
*   **Server_Age (服务器天数)**：玩家所属服务器的开服天数。
*   **Match_Pool (匹配池类型)**：
    *   `Global_Pool` (全服大池)：包含所有服务器的活跃玩家池。
    *   `Local_Pool` (本服小池)：仅包含本服务器玩家的独立池。

### 4.2 场景算法逻辑

#### 场景 1：正常均值战力玩家 (开荒/同水平组队)
*   **用户画像**：战力在副本推荐范围内，寻求正常游戏体验，不希望被拖累也不追求被秒带。
*   **判定条件**：`Dungeon_Min_CP <= Player_CP <= Dungeon_Cap_CP`
*   **匹配规则**：
    1.  **阶段一：本服优先 (Local First)**：
        *   进入 `Local_Pool` (本服小池)。
        *   **等待 10秒**：寻找本服 CP 差异在 ±20% 内的队友。
    2.  **阶段二：全服扩展 (Global Expansion)**：
        *   若 10秒 未匹配成功，自动扩展至 `Global_Pool` (全服大池)。
        *   寻找全服范围内的合适队友。
    3.  **阶段三：兜底 (Fallback)**：
        *   若总等待时间超过 30秒，填充 AI 队友。
*   **体验目标**：优先维系本服社交关系，其次保证匹配效率。

#### 场景 2：低战力玩家 (打不过求带)
*   **用户画像**：战力低于推荐或刚达标，操作不熟练，希望有“大腿”带飞。
*   **判定条件**：`Player_CP < Dungeon_Min_CP` (若允许进入)。
*   **匹配规则**：
    1.  **阶段一：本服求援 (Local Help)**：
        *   进入 `Local_Pool`。
        *   **等待 15秒**：优先寻找本服的高战玩家 (`CP > Cap`)。
    2.  **阶段二：全服求援 (Global Help)**：
        *   扩展至 `Global_Pool`。
        *   寻找全服的高战玩家。
    3.  **阶段三：正常/AI兜底**：
        *   若无高战，匹配正常玩家；最后由 AI 协助。
*   **体验目标**：优先让本服大佬带，增加本服膜拜感；实在没有再找跨服大佬。

#### 场景 3：高战力玩家 (带人/碾压/竞速)
*   **用户画像**：战力远超副本需求，目的是刷资源或快速通关。
*   **痛点修正**：防止跨服匹配到更老服务器的“巨佬”，导致本服第一变成跨服小弟。
*   **判定条件**：`Player_CP > Dungeon_Cap_CP`
*   **匹配规则**：
    1.  **代际隔离判定**：
        *   若 `Server_Age` 处于老服阶段（相比新服），**无法进入 `Global_Pool`**。
        *   **结果**：被强制锁定在 `Local_Pool`。
    2.  **筛选逻辑**：
        *   **本服匹配**：尝试在 `Local_Pool` 中寻找队友（高战或低战）。
        *   **自然隔离**：若本服无匹配对象（因为老服玩家不打低级本），则一直等待直到超时。
        *   **AI 兜底**：超时后分配 AI 队友（单机体验）。
    3.  **非老服情况**（同代际）：
        *   遵循 **场景 1** 的逻辑：先本服 (10s)，后跨服。
*   **体验目标**：**我是头部**。在物理上隔离了与新服玩家的接触，避免了数值碾压破坏新服生态，同时保证高战玩家随时有本打（虽然是打人机）。

### 4.3 补充规则体系 (Supplementary Rules)

为了完善匹配体验，除了核心算法外，必须明确以下维度的执行细则（对应第2章梳理的维度）。

#### 1. 匹配优先级 (Priority & Weight)
系统在 `Global_Pool` 池中筛选队友时，严格遵循以下权重顺序：
1.  **社交关系 (Social First)**：
    *   **P0**: 邀请列表/预组队 (Premade)。
    *   **P1**: 同公会成员 (Guild Member) 在队列中。
    *   **P2**: 好友列表 (Friend List) 在队列中。
2.  **职能互补 (Role Balance)**：
    *   若副本有硬性机制（如承伤/治疗检测），优先匹配 **骑士/贤者**。
    *   *注：纯 DPS 队伍若战力碾压 (CP > Cap)，可忽略此条。*
3.  **战力匹配 (CP Match)**：
    *   优先匹配 `Player_CP` ±10% 的玩家。
4.  **等待时长 (Wait Time)**：
    *   每等待 5秒，战力匹配范围扩大 5%。
    *   达到 30秒，触发 **AI 填充**。

#### 2. 社交转化与保留 (Social Retention)
匹配不仅是打本，更是社交的起点。Beagle 采用以下机制促进弱关系向强关系转化：
*   **点赞/互粉机制 (Like System)**：
   *   副本结算时，弹出“点赞”界面。同服好友增加添加好友按钮，点击后自动发送添加好友请求。
*   **公会引流 (Guild Funnel)**：
    *   若都是同服玩家，且队伍中 3人来自同一公会，通关后系统自动向路人玩家发送“公会邀请函”（若路人无公会）。

#### 3. 惩罚与限制机制 (Restrictions & Penalties)
鉴于移动端轻量化定位，惩罚机制以“软性引导”为主，避免硬核劝退。
*   **挂机/跳车 (AFK/Leaver)**：
    *   **AI 接管**：玩家掉线或长时间未操作，角色自动进入“AI 托管模式”，跟随队长行动。
    *   **收益衰减**：托管状态下，最终掉落收益减少 50%。
    *   **恶意退队**：手动退队 3次/日 内无惩罚（宽容度）；超过 3次 触发 10分钟 匹配冷却。
*   **战力门槛 (CP Gate)**：
    *   **硬门槛**：`CP < Dungeon_Min_CP` 无法进入匹配队列（除非在预组队中被队长拖进去）。
    *   **软上限 (Soft Cap)**：对于 **场景 3 (高战)** 玩家，若进入低级副本，其属性（攻击/防御）将被系统 **动态压缩** 至 `Dungeon_Cap_CP` 水平，但保留技能机制优势。这避免了高战玩家在低级本“抢怪”导致新人无体验。

### 4.4 规则总结表 (Rule Summary)

| 玩家状态 | 判定公式 | 匹配池归属 | 匹配对象范围 | 核心体验目标 |
| :--- | :--- | :--- | :--- | :--- |
| **正常 (Normal)** | `Min <= CP <= Cap` | 全跨服标准池 | 全跨服同战力区间玩家 | 势均力敌，正常社交 |
| **低战 (Weak)** | `CP < Min` | 全跨服标准池 | 优先高战 + 正常玩家 | 被带飞，顺利通关 |
| **高战 (Strong)** | `CP > Cap` | 全跨服标准池 (受限) | 同代际玩家 (高战/正常/低战) | "我是头部" (无老服压制) |

## 5. 基于动态分区 (Scheme 2) 的进阶匹配策略

结合 `docs/scheme2_detailed_design.md` 的“分线岛 -> 大世界”架构，匹配系统需在不同阶段执行差异化的优先级逻辑，并引入特殊的战力保护机制。

### 5.1 匹配池的阶段性定义 (Phase-Based Pool)

#### 第一阶段：分线岛时期 (Phase 1: Zone / Branch Island)
此阶段玩家处于独立的 Zone (如 Zone 1001, Zone 1001-A)，社交圈子较小，匹配核心是 **“快速成团”与“沉浸感”**。
*   **优先级逻辑**：
    1.  **P1 - 同分线岛 (Local Zone)**：优先匹配同一物理空间 (Zone 1001) 的玩家。
        *   *目的*：玩家在副本中遇到的队友，出本后能在主城直接看到，促进强社交转化。
    2.  **P2 - 同批次分线岛 (Same Batch)**：扩大至开服时间相近的 Zone (如 Zone 1002)。
        *   *算法*：`|Zone_ID_Diff| < 5`。
    3.  **P3 - 全服分线岛 (Global Zones)**：仅限新手引导副本或无门槛娱乐本。

#### 第二阶段：大世界时期 (Phase 2: Server / Big World)
此阶段玩家已合并进入完整的 Server (如 Server 001)，匹配核心是 **“本服社交为主，跨服效率为辅”**。
*   **优先级逻辑**：
    1.  **P1 - 同服务器 (Same Server)**：绝对优先匹配 Server 001 内的玩家，巩固公会/阵营关系。
    2.  **P2 - 邻近服务器 (Adjacent Servers)**：若本服匹配超时 (>30s)，扩大至 **开服时间相差 < N天** 的邻近服务器。
        *   *动态窗口*：系统维护一个 `Match_Group_ID`，通常将开服时间在 7-14天内的服务器划为一个匹配组。

### 5.2 跨服战力保护机制 (Chicken Head Protection)
针对 **“全服第一在新本变小弟”** (Chicken Head vs Phoenix Tail) 的痛点，设计 **动态封锁机制**。

#### 问题背景
Server 001 (开服100天) 平均战力 100k，Server 010 (开服10天) 平均战力 10k。若直接跨服匹配，Server 010 的“榜一大哥”在老服普通玩家面前毫无存在感，严重挫伤付费体验。

#### 解决方案：动态代际隔离 (Dynamic Generation Isolation)
1.  **新本保护期 (New Dungeon Protection)**：
    *   当服务器解锁新副本/新等级上限时，该副本在 **X 天内 (如 30天)** 仅允许 **同代际 (Same Generation)** 服务器匹配。
    *   **判定公式**：`|Server_Open_Time_A - Server_Open_Time_B| <= Generation_Gap (e.g., 7 days)`。
2.  **池子隔离 (Pool Separation)**：
    *   **老服玩家**：对于处于“新服保护期”的副本，老服玩家被禁止进入 `Global_Pool`，强制分流至 `Local_Pool`。
    *   **结果**：因为 `Local_Pool` 人少，老服玩家实际上在玩单机（匹配 AI），不会干扰新服生态。
3.  **追赶机制 (Catch-up Mechanism)**：
    *   只有当 Server New 的 **世界等级 (World Level)** 或 **平均战力** 达到 Server Old 的 **90%** 时，池子隔离才会解除，允许进入 `Global_Pool`。
