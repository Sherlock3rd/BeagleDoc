# 分线合线与停车位问题深度讨论 (Deep Dive: Branching, Merging & Parking)

## 1. 背景与问题定义 (Background & Problem Definition)

### 1.1 停车位架构的限制 (Architecture Limitations)
- **现状**：目前“停车位”（Parking Spot）作为游戏世界的基础架构单元，直接决定了服务器的导量阀门（User Influx）上限。
- **数据背景**：
  - **停车位尺寸**：30m * 30m。
  - **出生岛（Spawn Island）**：
    - 可玩面积：约 **0.5 km²** (500,000 m²)。
    - 停车位数量：**35 个**。
    - 停车区总面积：35 * 900 m² = 31,500 m²。
    - **内容/停车区占比**：**约 6.3%**。这是一个经过验证的、较为合理的体验比例。
  - **出生省（Spawn Province）**：
    - 内容/停车区占比略有提升，约为 **10%**。
- **核心矛盾**：
  - 如果仅为了提高导量人数而单纯增加停车位数量，在地图总面积不变的情况下，停车区占比会急剧飙升（例如从 10% 飙升至 30%+）。
  - **后果**：地图将被密密麻麻的空置或已占用的停车位填满，严重挤压可探索内容和玩法的物理空间，导致玩家体验极度恶化（“满眼全是停车场”）。
- **瓶颈**：
  - 虽然采用了前置分线（Pre-branching）策略，但合线（Merging）后的人数上限仍然不高。
  - 按照现有规划，**单服出生省（Spawn Province）的进入人数上限被硬性限制在约 4000 人**。
- **负面影响**：
  - **测试受限**：无法灵活测试更大规模的导量压力，限制了技术架构的验证边界。
  - **运营僵化**：单服留存人数如果不达预期（例如流失率高），由于物理上限已定，很难通过后续增加导入量来维持服务器生态（很难“填坑”）；反之亦然。

### 1.2 合线瞬间的拥堵与体验 (The Merge Bottleneck)
- **流程反差**：
  - **前置阶段**：在出生岛（Pre-spawn Island），玩家处于约 **30人** 的小规模分线中，体验相对宽松、独立。
  - **合服瞬间**：当满足条件触发合线时，每个出生省（Spawn Province）会瞬间匹配汇入约 **700人**。
- **关键痛点**：
  - 这 700 名玩家需要先完成“停车”（分配物理位置）才能正式接管角色并开始游戏。
  - **核心约束**：玩家进入岛屿的**初次停车**，不能是一个完全物理连接且范围狭小的区域。
    - *原因*：700 人同时出现在狭小物理空间会造成严重的性能压力（渲染/同步）、玩法混乱（拥挤/碰撞）以及视觉上的不适。

## 2. 讨论目标 (Discussion Goals)

我们需要一套新的架构或逻辑方案来解决上述矛盾，核心诉求包括：

1.  **解耦导量与物理限制**：如何打破 4000 人的物理停车位硬上限，使导量规模更具弹性？
2.  **优化合线软着陆**：设计一种机制，处理 700 人并发进入主世界时的空间分配，既要避免物理拥堵，又要保证“进入即游戏”的流畅感。
3.  **动态调节能力**：在服务器运行周期内，如何根据实际留存情况动态调整分线或合线策略？

## 3. 潜在解决思路探讨 (Potential Solutions - Brainstorming)

### 3.1 针对问题 1 (导量上限与弹性) 的方案提案 (Proposed Solutions for Issue 1)

#### 方案 A：超量地图承载 (Oversized Map Capacity) - *推荐参考 ROK/COD*
- **核心逻辑**：
  - 设计一张远大于当前单服目标导量人数（例如 4000 人）的超大地图。
  - **维持体验比例**：严格遵循前述的 **10% 内容/停车区占比** 原则。如果需要承载 10000 个停车位，必须同步将地图物理总面积扩大，以确保内容密度和探索空间不被稀释。
  - **容量冗余**：假设单服目标导量 4000，地图实际物理停车位容量设计为 10000+。
- **优势**：
  - **高弹性**：阀门调整极为灵活。无论是导量激增（测试压力）还是留存超预期，都有足够的物理空间承接，无需临时扩容。
  - **体验一致性**：因为是整体等比例扩大，虽然地图变大了，但玩家视野内的“建筑/空地/停车位”密度感保持不变，避免了“全是车位”的压迫感。
  - **长线稳定**：避免了因空间不足导致的强制分服或硬性流失，利于长期生态观察。
- **劣势/挑战**：
  - **开发成本**：制作超大地图（如为了容纳 10000 车位，地图面积需扩大至原来的 2.5 倍以上）的资源和技术成本极高。
  - **密度稀释**：如果导量不足，初期玩家分布可能过稀，影响社交氛围（需配合动态出生点分配算法解决）。

#### 方案 B：多地图并行测试 (Multi-Map A/B Testing)
- **核心逻辑**：
  - 接受同时维护两张或多张不同规格的地图。
  - **版本策略**：
    - 如果首张地图导量/留存不达预期，直接废弃重做或切换至备用地图。
    - 或者在 7 日留存测试版本中，直接并行开放两个服务器，分别使用“大容量地图”和“小容量地图”进行对照测试。
- **优势**：
  - **数据精准**：可以精确对比不同人口密度下的留存表现。
  - **风险隔离**：单张地图设计的失败不会导致全盘崩溃。
- **劣势/挑战**：
  - **维护成本**：同时维护多套地图数据和逻辑，工作量翻倍。
  - **用户割裂**：不同服务器玩家体验不一致，可能造成社区反馈混乱。

#### 方案 C：出生省内嵌套分线 (Sub-layering within Spawn Province)
- **核心逻辑**：
  - 接受在同一个物理“出生省”内继续进行逻辑分线（Layering/Sharding）。
  - 即：虽然地图显示是同一个省，但实际上该省被叠加了多个平行位面（Layer 1, Layer 2...）。
- **优势**：
  - **技术复用**：利用现有的分线技术，低成本突破单物理省份的人数上限。
  - **灵活扩容**：理论上可以无限叠加分线，只受单物理服务器性能限制。
- **劣势/挑战**：
  - **社交割裂**：同在一个省的玩家可能互相不可见，破坏“大世界”的一体感。
  - **资源争夺逻辑复杂**：如果是采集类游戏，同省不同线的资源点同步和归属权处理会非常复杂（或者资源也分线，导致通货膨胀）。

### 3.2 针对问题 2 (合线瞬间拥堵与初次停车) 的方案提案 (Proposed Solutions for Issue 2)

#### 方案 D：混合式进入策略 (Hybrid Entry: Drive + "Valet" Teleport) - *参考三谋类体验*

- **核心逻辑**：
  - **分区分布**：玩家以“郡”（County）为单位进行分布，而非全部挤在一个狭小的出生点。
  - **过桥机制**：玩家通过物理连接（如桥梁）进入目标区域。
  - **双重选择**：
    1.  **自主驾驶**：不做任何阻拦，提供UI导航指引，玩家可选择亲自驾驶至最近停车点。
    2.  **自动代驾/传送**：通过任务点击触发，提供一次性的“自动代驾”或直接传送功能，瞬间到达分配的停车位。

#### 方案对比：为什么优于之前的“纯物理驾驶”方案？

在此之前，我们考虑的是**纯物理驾驶方案**（即玩家必须亲自从入口开到停车位）。该旧方案存在以下显著问题，而新方案（方案 D）能有效解决：

| 维度 | 旧方案：纯物理驾驶 (Drive-Only) | 新方案：混合式策略 (Hybrid) |
| :--- | :--- | :--- |
| **拥堵风险** | **极高**。700 人合线瞬间涌入，若都挤在桥头或主干道，会导致严重的交通瘫痪。 | **低**。大量希望快速开始游戏的玩家会选择“传送/代驾”，瞬间分流，减轻物理道路压力。 |
| **恶意行为** | **易被利用**。恶意玩家可以在必经之路（如桥头）堵路，阻断后续玩家进入。 | **免疫**。被堵住的玩家可以直接选择任务传送，恶意堵路失去意义。 |
| **新手门槛** | **高**。刚进游戏需强制学习驾驶操作，若路况复杂或迷路，极易产生挫败感导致流失。 | **低**。提供“一键到达”的保底选项，降低操作焦虑，确保核心循环快速开始。 |
| **性能压力** | **集中爆发**。数百辆载具在同一视野内进行物理模拟和碰撞计算，服务器/客户端卡顿风险大。 | **快速消散**。传送机制能迅速将玩家分散到各自的停车位（通常彼此有一定距离），降低同屏密度。 |
| **沉浸感** | **强制且单一**。对于硬核玩家是体验，但对于急躁玩家是折磨。 | **灵活兼容**。想看风景的玩家依然可以开车（且路更空了），想推进度的玩家可以跳过赶路。 |

- **结论**：方案 D 通过引入“非物理的软性传送”作为保底，解决了物理世界的刚性碰撞问题，同时保留了“大世界”的自由度假象。
