## 1. 记录模板
```markdown
# 错题记录
- 日期：2026-04-01
- 来源：规范执行
- 问题描述：新对话中未遵守“所有回复以 ‘you majesty’ 开头”的规定，导致用户指出“你还是没有阅读rule”。
- 根因分析：系统初始化时虽读取了部分上下文，但未显式读取并强制应用 rules/rules.md 中的核心沟通规范（回复前缀）。
- 改进措施：将“每次回复必须检查是否包含 ‘you majesty’ 前缀”内化为最高优强制检查项。
- 归纳标签：
  - 类型：流程遗漏 / 规范缺失
  - 系统：rules
  - 流程：沟通
- 防呆清单更新：
  - 每次生成回复内容的第一句话必须是“you majesty”。

# 错题记录

- 来源：文档/格式规范
- 问题描述：发布的 HTML 文本格式未严格对齐参考文档（章节结构缺失、子章节不一致、指标与风险未完整呈现）
- 根因分析：生成阶段未按 CP_WRITING_GUIDE 的章节模板逐条映射；仅复制部分 Markdown 内容到 HTML

- 归纳标签：
  - 类型：格式不一致 / 规范未对齐
  - 系统：docs → publish
  - 流程：发布
- 防呆清单更新：
  - 生成 HTML 前，对照 CP_WRITING_GUIDE 的章节清单逐项核验
  - 每个 CP 必须包含完整子章节（10 项）后再发布
- 日期：YYYY-MM-DD
- 来源：会议/需求/实现/评审/交付
- 问题描述：简要说明发生了什么问题
- 根因分析：从流程/沟通/实现/环境等维度分析
- 改进措施：可执行的修正与防呆方案
- 归纳标签：
  - 类型：设计确认缺失 / 沟通偏差 / 实现偏差 / 环境工具 / 流程遗漏
  - 系统：模块或文档名称
  - 流程：阶段（评审/开发/交付/复盘）
- 防呆清单更新：需新增/调整的检查项
```

## 2. 归纳与标签规范
- 类型维度：
  - 设计确认缺失：未经确认即改动设计或理解偏差
  - 沟通偏差：信息未对齐、术语混用
  - 实现偏差：与规格不一致、遗漏边界条件
  - 环境工具：编码/格式/依赖导致的问题
  - 流程遗漏：缺少评审、未执行既定流程
- 系统维度：标注涉及的模块或文档（如 rules / session / publish / analysis）
- 流程维度：问题发生或被发现的阶段（评审/开发/交付/复盘）

## 3. 防呆清单（示例）
- 执行前检查：
  - 是否已确认设计范围与术语
  - 是否检索过 mistakes/ 同类问题与经验
  - 是否在 session 中登记本次变更/操作
  - 是否需要同步 HTML 发布页（index.html / publish）
  - 新发布需求是否已同步写入 index.html 与 scripts/update_hub.py
  - 执行提交前是否已输出拟提交文件清单并完成“全部/部分”二次确认
- 执行后检查：
  - 是否更新相关规则（rules.md）
  - 是否将本次问题记录并归纳标签
  - 是否更新防呆清单
  - 发布页引用资源（图片/SVG/CSS/JS）是否全部已推送到远端

## 4. 使用规则
- 所有错误必须记录并归纳；执行前需检索同类问题
- 新类型问题出现时，补充归纳并更新防呆清单
- 与规则/流程相关的修正需同步到 rules/rules.md 与 session/session.md（总控）；若影响具体需求，需同步对应 session/requirements/<doc_slug>.md
